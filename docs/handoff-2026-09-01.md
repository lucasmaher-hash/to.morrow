## The submission situation

The app **was submitted and rejected** — Apple ID `6798337661`, App Store
Connect shows "1.0 Rejected".

**The rejection is Guideline 2.1 Information Needed.** Nothing is wrong with
the app. The App Review Information section was left blank, so the reviewer had
no way in and could not complete a review. Apple asked for seven things in the
Notes field:

1. A screen recording on a **physical device** showing the core flow
2. The device models and OS versions tested
3. A description of the app's functions and target audience
4. Setup instructions and any credentials
5. External services used
6. Regional differences
7. Documentation for regulated content or third-party material

**Answers already established from the code**, so a new session need not
re-derive them:

- **4. Credentials:** none. No account, no login anywhere in the app.
- **5. External services:** none. Zero remote Swift packages. CloudKit only,
  which is Apple's own.
- **6. Regional differences:** none. The app is English-only; the language
  picker that promised otherwise was removed on 2026-09-01. Dates and weekday
  names follow the device locale via `Calendar`/`DateFormatter`.
- **7. Third-party material:** the **W95FA** typeface, under the SIL OFL.
  `shove95/shove95/Resources/W95FA-LICENSE.txt` ships in the bundle.

Items 1 and 2 are the founder's — they need a real device.

**Two things that will bite at upload:**

- App Store Connect still has the version numbered **1.0**. A build stamped
  `1.1` will not attach to a 1.0 version record. Either edit that version's
  number to 1.1 (it is editable while unreleased) or add a new 1.1 version.
- Uploading does not resolve the rejection. The Notes field must be filled
  before submitting for review again.

## Things a new session will otherwise get wrong

**The Xcode project is one level down.** Repo root is `shove-95/`, the project
is `shove95/shove95.xcodeproj`. Running `xcodebuild` from the root fails with
`'shove95.xcodeproj' does not exist`. This cost time twice.

**Use the `shove95` scheme.** Three exist — `shove95`, `Shove95Kit`,
`ShoveWidgets` — and archives were accidentally made from `ShoveWidgets`. The
`shove95` scheme may be hidden; tick Show (and Shared) in Manage Schemes.

**Both targets carry the version.** `shove95` and `ShoveWidgets` each hold
`MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` in Debug *and* Release —
eight places. An extension whose version disagrees with its app fails
validation at upload. Always verify in the **built binary**, not the project
file.

**`ShoveWidgets` is not a widget.** It contains one `ActivityConfiguration` —
the Lock Screen Live Activity. Live Activities can only live in a widget
extension. Deleting the target deletes "Go live". No Home Screen widget exists
and none appears in the widget gallery.

**Do not "improve" the demo seed content.** `TaskStore.seedDemo()` holds the
founder's own screenshot list, transcribed from the simulator's SwiftData
store. Lower-case openings, two ticked-off rows and a photo-less bike light row
are all deliberate. A previous pass restored a deleted row and corrected a
title; the founder objected. Leave it alone.

**The simulator has two identities.** `iPhone 17` (7941F55D) is signed into
iCloud with the founder's **real tasks** — never seed there. `iPhone 17 Pro Max`
(79DCA773) is the clean one. A throwaway `shove95 shots` iPhone 17 was created
for screenshots; delete with `xcrun simctl delete "shove95 shots"`.
